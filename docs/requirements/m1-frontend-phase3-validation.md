## 本阶段实现

- 我的预约：全部/五种预约状态筛选、分页、总数、刷新。切换状态回到第一页；删除末页最后一条后自动返回有效页；旧请求不能覆盖较新的筛选。
- 详情：请求 `/api/m1/bookings/{id}` 获取最新数据，展示预约与座位编号、完整年份的北京时间、当前状态及创建/取消时间。未提供教室或座位名称时不编造。
- 取消：先加载详情并二次确认；只有 BOOKED 提供操作入口，最终权限和时点由服务端确认。403/404 后阻止重复写入，409 刷新实际状态；资源释放仍由后端实现。
- 编码签到：提交 CODE 和去除首尾空白的用户编码，空输入阻止提交；没有臆定编码长度、没有浏览器内置有效码。成功后重新读取预约状态；错误或过期编码允许修正。
- 再次预约：默认填当前时间推导出的新时段，不复制旧预约日期；发送 original_booking_id 和新的北京时间。校验整点、先后关系、默认 4 小时限制；冲突保留输入供修改，历史预约不被覆盖。
- 违约记录：独立查询、分页、类型与发生时间、关联预约详情。前端不自行产生违约、不代替后台计时，不声称已经发送通知。
- 写入并发防护：签到、取消、复约共用一次操作锁，处理中不允许重复提交或关闭弹窗；操作成功和后续刷新失败分开反馈；超时/断网提示先确认记录再操作。

主要实现文件：`frontend/src/components/m1/PersonalBookings.vue`、`frontend/src/composables/useM1Personal.js`。M1.vue 集成新区域；M1 API 适配器补充既有契约路径；预约成功回调刷新新个人列表，保留第二阶段查询交互。未修改公共请求工具、路由、依赖声明、数据库或其他模块代码。

3. 重置历史场景，找到已预约记录。签到先试空输入/错误码，再用 `482916` 验证成功；此编码仅用于本地模拟。
4. 对另一条已预约记录打开取消弹窗，先返回确认没有取消，再正式确认；状态或当前筛选结果应刷新。
5. 对历史记录点击“再次预约”，选择新的 1～4 小时整点时段。与测试已有预约重叠会提示冲突；可改为另一天重试。成功后新记录出现，原记录不变。
6. 点击“查看违约记录”，翻页并查看关联预约。切换顶部无权限、详情不存在、编码过期及刷新失败场景检查反馈。
7. 缩窄窗口检查手机操作。预览进程重启或切换场景会重置数据，不涉及真实数据库。
