
5.1 Database Schema
数据表	字段及类型
seat_bookings	id BIGINT PK, user_id BIGINT FK, seat_id BIGINT FK, reservation_id BIGINT, start_time DATETIME, end_time DATETIME, status VARCHAR(20), created_at DATETIME, cancelled_at DATETIME
seat_checkins	id BIGINT PK, booking_id BIGINT FK UNIQUE, checkin_method VARCHAR(20), checkin_time DATETIME
booking_violations	id BIGINT PK, user_id BIGINT FK, booking_id BIGINT FK UNIQUE, violation_type VARCHAR(30), occurred_at DATETIME
booking_settings	setting_key VARCHAR(50) PK, setting_value VARCHAR(255), updated_at DATETIME
预约状态：
BOOKED / CHECKED_IN / CANCELLED / NO_SHOW / COMPLETED

5.4 座位预约接口
POST /api/m1/bookings
请求：
{
  "seat_id": "301",
  "start_time": "2026-10-23T09:00:00+08:00",
  "end_time": "2026-10-23T11:00:00+08:00"
}


成功响应：
{
  "code": "OK",
  "message": "预约成功",
  "data": {
    "id": "501",
    "user_id": "101",
    "seat_id": "301",
    "reservation_id": "401",
    "start_time": "2026-10-23T09:00:00+08:00",
    "end_time": "2026-10-23T11:00:00+08:00",
    "status": "BOOKED",
    "created_at": "2026-10-22T14:00:00+08:00",
    "cancelled_at": null
  },
  "request_id": "req-006"
}


接口必须满足以下条件：申请时段按整点小时计，单次预约不超过配置的上限（默认 4 小时），用户具有预约权限，座位和教室都处于可用状态，且 D2 成功建立资源占用。
M1 调用 D2 创建占用后，应将该占用确认，再将 reservation_id 存入 seat_bookings。不可以只写入 M1 预约表而不调用 D2。
5.5 签到与违约规则
签到：
POST /api/m1/bookings/501/checkin


{
  "checkin_method": "CODE",
  "code": "482916"
}


时间	系统动作
预约开始前 15 分钟	发出第一次提醒
预约开始后 10 分钟	未签到则再次提醒
预约开始后 15 分钟	未签到则标记 NO_SHOW、释放资源并记录违约
正常签到	BOOKED → CHECKED_IN
学习时段结束	CHECKED_IN → COMPLETED
提醒、动态签到码以及定时检查机制是需求文件规定的功能，但现有四张 M1 数据表没有保存提醒记录或动态签到码的字段。可以通过定时任务、缓存和通知接口实现；如果需要持久化追踪，则要补充 Schema。
