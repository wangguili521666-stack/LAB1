1. **业务缺口**：同步预约时长配置到学生查询/预约/历史复用；验收“上限6允许5、拒绝7，上限2拒绝3”，前后端一致。接通一种真实外部通知渠道并记录前15/后10/违约通知送达及失败重试。
2. **发布闭环**：评审合入PR #3，main完整CI成功，经人工批准发布第二版，实际生产回退并恢复；补Git tag（按课程口径）、每版变更清单和版本证据。
3. **小组过程材料**：成员/模块认领、D层归属ADR、候选方案与取舍、实际组内确认、风险及依赖台账、伦理决定和个人论文。只能据真实讨论补记，标明补记时间，不能伪造历史会议。
4. **验收闭环**：逐条处理100条pending_acceptance，记录断言/操作结果；执行D3跳过的真实数据库专项，修复M2审计持久重试这一已登记内部需求；准备五项现场演示脚本。
