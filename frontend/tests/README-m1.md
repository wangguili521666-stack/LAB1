# M1 第二阶段测试与预览

本阶段为查询与预约前端；真实 M1/D2 服务尚未在本仓库提供。模拟预览不产生真实预约，不证明后端鉴权、资源释放或并发控制。

## 自动测试

在已按 `frontend/package-lock.json` 正确安装依赖的前端目录运行：

```powershell
node --test tests/auth.test.mjs tests/m1.test.mjs tests/m1-api.test.mjs
npm.cmd run build
```

当前仓库仍跟踪旧的 node_modules，直接在原目录重装可能产生大量无关变更。建议在独立副本中复制 package.json、package-lock.json、index.html、vite.config.js、src、tests、scripts，再执行 `npm.cmd ci`。不要将依赖重装产生的改动混入 M1 功能提交。

## 可交互验收

在前端目录启动：

```powershell
node scripts/m1-preview.mjs
```

打开 `http://127.0.0.1:5174/tests/m1-preview.html`。顶部始终标记“模拟接口”，可以选择正常、空结果、预约冲突、服务异常、成功后刷新失败、慢速响应场景。点击“切换场景并重置”清除测试数据。

该页面直接加载真正的 M1.vue、请求适配和状态逻辑，只将 HTTP 响应换为本机测试数据。脚本仅绑定 127.0.0.1。生产构建只从 index.html 入口构建，不导入这个 HTML、预览脚本或测试数据。正常 `npm run dev` 不启用模拟接口。

测试目录：教学楼 A / 教室 201 / 学院 1 有固定插座 A01、导轨插座 A02；图书馆 / 教室 202 / 学院 2 有无插座 B01。这些都是虚构测试数据。测试服务只实现验收所需有限响应，不是可部署后端。

人工操作：查询后选择座位 → 核对时间 → 返回或确认；修改筛选后旧结果应禁止预约；选择慢速场景连续点击确认只创建一条记录；选择冲突场景应提示重新选择；选择刷新失败场景应同时保留预约成功和读取失败说明。调整浏览器宽度检查手机布局。

## 可选浏览器自动验收

`m1-browser.cjs` 使用 Playwright，未为此修改共享 package.json/lock。先在独立工具环境安装 Playwright 和浏览器，再设置 `M1_PLAYWRIGHT_MODULE` 为该包绝对路径；已有可兼容 Chromium 浏览器时可设置 `M1_BROWSER_PATH` 为可执行文件路径。默认使用 Playwright 的 Chromium。

预览服务运行时执行 `node tests/m1-browser.cjs`。可用 `M1_PREVIEW_URL` 设置地址，用 `M1_QA_OUTPUT` 设置截图和 JSON 报告的输出目录，建议使用仓库外的临时目录。

覆盖查询/筛选、过期结果、键盘关闭与焦点恢复、慢响应重复提交、409/503/网络错误、成功后刷新失败、375/768/1440 布局、真实 App 壳和 401 跳转。浏览器用模拟接口，报告不会将其标记为真实后端通过。
