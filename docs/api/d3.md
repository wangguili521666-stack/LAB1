# D3 v0.1：通知、个人消息、公告与操作审计

首版开发契约，2026-10-23。D3 的范围扩展为通知、个人消息、公告与审计，供其他模块先用 Mock 联调。权限、公告版本字段和通知格式为首版约定，合入共享环境前需参与模块评审。

## 1. 职责和约定

- M1 决定 T−15、T+10 提醒，执行 T+15 违约、取消和资源释放；D3 不计算这些业务时机。
- M2/M3 决定审批/维修事件、内容和收件人；D1 负责用户和角色；D3 只操作自己的表。
- 当前实现站内消息、已读、公告和审计。EMAIL / WECHAT 返回 422 CHANNEL_NOT_AVAILABLE；尚无外部投递队列、发送重试、回执或模板引擎。
- 返回包装、ID 字符串和分页遵循 [common.md](common.md)。时间接收带时区 ISO 8601，输出 UTC（Z）；数据库也存 UTC。筛选区间左闭右开。
- JSON 不接受未知字段；标题最多 200、正文最多 10000 字符，请求体上限 64KB。正文按纯文本解释，前端不得直接渲染未清洗 HTML。
- 每个响应含服务端生成的 request_id 和 X-Request-Id。客户端 trace_id 仅用于关联，不充当身份或幂等键。

## 2. 身份与权限

| 接口 | 认证 | 首版权限 |
|---|---|---|
| 公共公告、健康检查 | 无 | 只返回有效已发布公告 |
| /messages/me... | Authorization: Bearer <D1用户令牌> | 当前用户本人 |
| 公告写操作、/admin/announcements... | 同上 | OPERATION_ADMIN 或 SYSTEM_ADMIN |
| /admin/logs | 同上 | SYSTEM_ADMIN |
| /internal/... | X-D3-Service-Token: <独立服务凭据> | M1/M2/M3/D1/D2 可信后端 |

正式模式调用现有 GET /api/d1/users/me 核验账号和角色，不读取 D1 的表，不接受浏览器提交操作者 ID。D1 超时/故障返回 503，身份失效返回 401，停用账号返回 403。内部接口凭据映射到来源模块，不能通过请求体冒充其他模块。服务凭据只保存在后端环境变量，浏览器不得持有。

Mock 仅绑定 127.0.0.1，使用 [D3 README](../../backend/D3/README.md) 中的假身份，不连接真实 D1。正式启动入口不导入 Mock 身份。

2026-10-28 增加本机持久化开发入口 npm.cmd run dev:local：默认 http://127.0.0.1:3106，使用同样的模拟身份，但全部 D3 业务记录写入本机 MySQL 的 campus_d3_local。接口、权限和状态规则不变，重启不清空数据。该入口只能连接本机专用库；团队环境使用 .env 与 npm.cmd start，核验真实 D1 身份。

本地验收工具同时提供 `GET /local/d3/` 页面；仅 `dev:local` 挂载，不属于跨模块业务 API，不修改下面的接口契约。`GET /local/d3/session` 返回当前进程的页面会话键及本地库名/端口；`GET /local/d3/database` 用固定 SQL 读回四张业务表的计数；`POST /local/d3/request` 接收 `{actor, method, path, body?}`，仅转发本文件列出的业务接口和方法到同一服务。模拟身份只允许 public、student-101、student-102、operator-103、admin-104、M1/M2/M3/D1/D2，凭据由后端注入，认证与业务校验仍由原接口执行。后两项须携带 `X-D3-Local-Key` 页面会话键；全部本地工具请求检查回环连接、Host 和同源来源，禁止任意目标地址转发。失败仍使用统一错误包装；转发保留原状态码、错误码和 request_id。会话失效返回 403 LOCAL_SESSION_EXPIRED，刷新页面恢复；该工具不能用于团队或生产环境。

## 3. 内部通知

### POST /api/d3/internal/notifications

示例请求（时间需按实际事件更新）：

```json
{
  "source_event_id": "m1:booking:501:reminder-before:1",
  "notification_type": "BOOKING_REMINDER",
  "biz_type": "SEAT_BOOKING",
  "biz_id": "501",
  "recipient_user_ids": ["101"],
  "title": "预约即将开始",
  "content": "你的预约即将开始，请按时签到。",
  "channels": ["IN_APP"],
  "occurred_at": "2026-10-23T10:00:00+08:00",
  "expires_at": "2026-10-23T10:15:00+08:00",
  "trace_id": "m1-request-123"
}
```

| 字段 | 要求 |
|---|---|
| source_event_id | 必填，1–128 个 ASCII 字母/数字及 _ . : @ / -；同一事件重试保持不变 |
| notification_type | 必填，最多 64 字符，大写字母开头，仅含大写字母/数字/下划线，如 BOOKING_REMINDER、APPROVAL_RESULT |
| biz_type, biz_id | 必填，各最多 64 字符；biz_type 格式同 notification_type，biz_id 为非空业务 ID 字符串；均不能替代事件 ID |
| recipient_user_ids | 必填，1–100 个正整数 ID 字符串，重复用户去重；来源服务负责用户存在性和收件权限 |
| title, content | 必填，通知内容快照 |
| occurred_at | 必填，事件时间，不允许超过当前时间 5 分钟 |
| expires_at | 可省略/null，须晚于发生时间；过期事件仍可保存历史，但不计有效未读 |
| channels | 可省略，当前只能为 ["IN_APP"] |
| source_module | 可省略，填写时必须等于凭据所属模块 |
| trace_id | 可省略/null，最多 64 字符，不参与幂等比较 |

首次返回 201，原样重试返回 200：

```json
{
  "code": "OK",
  "message": "success",
  "data": {
    "id": "1",
    "deduplicated": false,
    "recipient_count": 1,
    "channel": "IN_APP",
    "delivery_status": "STORED",
    "is_active": true
  },
  "request_id": "服务端生成的请求标识"
}
```

幂等键为 (source_module, source_event_id, notification_type)。接收人排序去重、时间转 UTC 后比较内容，同键不同内容返回 409 RESOURCE_CONFLICT。通知、收件人和接收审计在一个本地事务内保存；成功仅表示站内消息已存储。

来源模块应在自己的业务事务中保留待发事件（Outbox 或等价机制），失败后用原事件 ID 重试。本轮没有修改来源模块或实现它们的 Outbox；只调用一次且不重试仍可能丢失事件。网络超时结果不确定时可重试；409 应先核对事件内容。

### POST /api/d3/internal/notifications/{id}/invalidate

请求体 {}，仅原来源模块可调用。返回 {id, invalidated_at}，重复调用保留首次失效时间，其他来源或不存在 ID 均返回 404。消息不删除，仍可查询历史。

调用方需保存通知响应 ID。该接口只失效这一条已接收通知，不能阻止之后以新事件 ID 创建通知；业务取消与事件发送顺序由来源模块协调。按业务键的失效屏障、乱序和外部发送中取消竞态留到后续阶段。

## 4. 个人消息

| 方法 | 路径 | 参数/请求 | 返回 data |
|---|---|---|---|
| GET | /api/d3/messages/me | is_read=true/false?, source_module?, page?, page_size? | 分页消息 |
| GET | /api/d3/messages/me/unread-count | 无 | {unread_count}，只计有效且未读 |
| GET | /api/d3/messages/me/{id} | 消息 ID | 本人消息，不自动标记已读 |
| POST | /api/d3/messages/me/{id}/read | {} | 消息，is_read=true |

消息字段：id（收件记录 ID）、notification_id、recipient_user_id、source_module、source_event_id、notification_type、biz_type、biz_id、title、content、trace_id、occurred_at、created_at、expires_at、invalidated_at、read_at、is_read、is_active。

- 消息 ID 与通知 ID 不同，从消息列表取得消息 ID 再标记已读。
- 按 created_at DESC, id DESC 排序，保留过期/失效历史。is_read=false 包含未读历史，因此总数可能大于有效未读徽标数；前端通过 is_active 提示失效。
- is_active 表示未手动失效且未到期。已读重试保留首次 read_at。
- 管理员也不能借此查看别人的消息；非本人记录统一返回 404。不提供替别人已读、删除消息接口。

## 5. 公告

保留既有路径，新增管理员详情和并发版本字段。

| 方法 | 路径 | 参数/请求 | 返回 data |
|---|---|---|---|
| GET | /api/d3/announcements | type?, page?, page_size? | 分页有效公告 |
| GET | /api/d3/announcements/{id} | 无 | 有效已发布公告 |
| GET | /api/d3/admin/announcements | status?, type?, published_from?, published_to?, 分页 | 分页全部状态 |
| GET | /api/d3/admin/announcements/{id} | 无 | 包含草稿/历史的公告 |
| POST | /api/d3/announcements | title, content, type, expires_at? | 201 草稿 |
| PATCH | /api/d3/announcements/{id} | expected_version 及至少一个 title/content/type/expires_at | 更新公告 |
| POST | /api/d3/announcements/{id}/publish | {"expected_version":1} | 发布公告 |
| POST | /api/d3/announcements/{id}/withdraw | {"expected_version":2} | 撤回公告 |

字段：原 id,title,content,type,publisher_id,status,published_at,expires_at,created_at,updated_at，新增 created_by,updated_by,withdrawn_at,version。用户 ID 全来自 D1 认证，客户端不可设置。

- 类型 NOTICE / MAINTENANCE / EMERGENCY，状态 DRAFT / PUBLISHED / WITHDRAWN。
- 创建为草稿、版本 1。修改/发布/撤回递增版本，过期版本返回 409。
- 草稿或撤回状态可编辑/发布；已发布公告先撤回再编辑，仅已发布状态可撤回。发布/撤回结果不确定时先读管理员详情，不盲目重复请求。
- expires_at=null 清除期限；指定期限须在未来；到期公告先修改期限再发布。
- 公共接口仅展示已发布、发布时间已到且未过期的公告。首版发布即生效，没有预约发布。
- 草稿 publisher_id 为创建人，实际发布时更新为发布人。每项写操作与审计一起提交。

## 6. 操作审计

### POST /api/d3/internal/logs

```json
{
  "module": "M1",
  "source_event_id": "m1:booking:501:create:1",
  "user_id": "101",
  "actor_type": "USER",
  "action": "BOOKING_CREATE",
  "target_type": "SEAT_BOOKING",
  "target_id": "501",
  "request_method": "POST",
  "request_path": "/api/m1/bookings",
  "result": "SUCCESS",
  "ip_address": "192.0.2.10",
  "occurred_at": "2026-10-23T10:00:00+08:00",
  "trace_id": "m1-request-123"
}
```

必填 action（最多 100 字符）、result（SUCCESS / FAILURE / DENIED），其他字段可省略：

- module 由服务身份确定，填写时须一致。user_id 为可信来源服务声明的上游操作者；D3 验证服务身份，不声称独立证明该用户实际执行了该操作。
- actor_type 默认为有用户时 USER、否则 SYSTEM；USER 必须有 user_id，SYSTEM/SERVICE 不能填写用户。
- source_event_id 格式同通知，填写时按 (module, source_event_id) 去重，内容冲突 409。兼容旧格式省略事件 ID 时每次追加，不保证去重；新调用应提供事件 ID。
- target_id 为 BIGINT ID 字符串，填写时必须有 target_type（最多 50 字符）。
- occurred_at 可省略，默认接收时间；created_at 总由 D3 生成，不接受客户端填写。
- request_path 最多 255 字符，只能是路径，禁止查询参数/片段；request_method 为 GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS；IP 须合法。
- trace_id 最多 64 字符，可选 reason 最多 1000 字符。
- 首次 201、重试 200，data 为 {id, deduplicated}。无日志修改或删除 API。

### GET /api/d3/admin/logs

仅 SYSTEM_ADMIN，可按 user_id,module,action,result,start_time,end_time,page,page_size 查询。时间范围按 D3 的 created_at 过滤。返回分页记录，包含上述字段及 id、created_at，不返回内部 payload_hash。

D3 自动审计通知接收/失效、首次消息已读、公告创建/编辑/发布/撤回、写操作失败和读取越权。自动审计不存请求体、令牌、密码、错误堆栈、URL 查询参数。上游也不得把敏感数据放进 reason、action 或路径。数据库不可用时无法保证审计落库，仅输出 request_id、code 诊断，后续需接入告警和日志收集。

## 7. 健康与错误

GET /api/d3/health 返回 {status:"UP",storage:"memory"或"mysql",channels:["IN_APP"]}，只检查 D3 存储，不代表 D1、邮件或微信可用。

| 状态 | 错误码 | 场景 |
|---|---|---|
| 400 | VALIDATION_ERROR | 字段、类型、时间或分页错误 |
| 401 | UNAUTHORIZED | 用户或服务身份缺失/无效 |
| 403 | FORBIDDEN | 角色不足、模块冒充、账号停用 |
| 404 | NOT_FOUND | 不存在、非本人记录或不可见公告 |
| 409 | RESOURCE_CONFLICT / INVALID_STATE | 幂等内容不一致、版本冲突、非法状态变更 |
| 413 | PAYLOAD_TOO_LARGE | 请求超过 64KB |
| 422 | CHANNEL_NOT_AVAILABLE / ANNOUNCEMENT_EXPIRED | 渠道未接入、过期公告发布 |
| 500 | INTERNAL_ERROR | 未预期的内部错误 |
| 503 | DEPENDENCY_UNAVAILABLE | D1 或数据库不可用 |
