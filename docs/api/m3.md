
7.1 Database Schema
数据表	字段及类型
repair_types	id BIGINT PK, type_name VARCHAR(50), default_priority TINYINT, sla_hours INT
repair_tickets	id BIGINT PK, ticket_number VARCHAR(50) UNIQUE, reporter_id BIGINT FK, repair_type_id BIGINT FK, classroom_id BIGINT FK NULL, location_description VARCHAR(255), description TEXT, priority TINYINT, status VARCHAR(30), assigned_to BIGINT FK NULL, assigned_at DATETIME, deadline_at DATETIME, escalation_count INT, completed_at DATETIME, accepted_at DATETIME, created_at DATETIME
repair_progress	id BIGINT PK, ticket_id BIGINT FK, operator_id BIGINT FK, action_type VARCHAR(30), old_status VARCHAR(30), new_status VARCHAR(30), description TEXT, created_at DATETIME
repair_reviews	id BIGINT PK, ticket_id BIGINT FK UNIQUE, reviewer_id BIGINT FK, rating TINYINT, comment TEXT, created_at DATETIME
原数据库没有明确列出 repair_tickets.status 的枚举值，因此根据需求与验收文件建议固定为：
PENDING_ASSIGNMENT / ASSIGNED / IN_PROGRESS / PENDING_ACCEPTANCE / COMPLETED / CANCELLED
其中 CANCELLED 为可选补充状态，支持任务书附加 Agent 功能。

POST	/api/m3/tickets/{id}/review	rating, comment?	RepairReview

POST	/api/m3/tickets/{id}/cancel	reason?	RepairTicket

其中：
RepairType = {id, type_name, default_priority, sla_hours}。
最后的内部接口可供受信任的定时任务调用，不应向普通登录用户开放。
7.4 报修接口
POST /api/m3/tickets
{
  "repair_type_id": "1",
  "classroom_id": "201",
  "location_description": "教学楼A 301",
  "description": "教室灯具损坏"
}


location_description 和 description 不允许为空。
M3 需要从 repair_types 获取 default_priority 和 sla_hours，生成唯一 ticket_number，计算 deadline_at，并建立 PENDING_ASSIGNMENT 工单。
7.5 工单状态转换
当前状态	操作	新状态
PENDING_ASSIGNMENT	物业管理员派单	ASSIGNED
ASSIGNED	维修工开始维修	IN_PROGRESS
IN_PROGRESS	维修工提交完工	PENDING_ACCEPTANCE
PENDING_ACCEPTANCE	报修人验收通过	COMPLETED
PENDING_ACCEPTANCE	报修人验收不通过	IN_PROGRESS
超时升级不一定改变工单主状态，而是：
- 根据 deadline_at 判断是否超时。
- 按既定规则更新 priority 和 escalation_count。
- 在 repair_progress 增加 ESCALATE 记录。
- 供物业管理员查询。
验收不通过时，必须提供返工原因，并产生 REWORK 进度记录。

7.6 M3 与 D2 的集成
根据课程任务书，一间教室出现“维修中”的报修工单后，该教室座位应当自动下架，验收通过后恢复。
建议 M3 在进入 IN_PROGRESS 时调用：
POST /api/d2/internal/maintenance/sync


{
  "ticket_id": "1001",
  "classroom_id": "201",
  "active": true
}


验收通过后：
{
  "ticket_id": "1001",
  "classroom_id": "201",
  "active": false
}


关键约定： 下架的是指定教室的资源可预约能力，而不是无条件删除或取消已有预约记录。已有预约如何通知、取消及补偿应另行定义。
对于没有 classroom_id 的故障，M3 不进行整教室下架。对于同一教室多个维修工单，D2 只有在所有生效的维修阻塞均结束后才能恢复开放。
