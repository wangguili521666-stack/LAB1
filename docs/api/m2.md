6.4 教室申请接口
POST /api/m2/applications
{
  "classroom_id": "201",
  "purpose": "学术研讨",
  "start_time": "2026-10-23T14:00:00+08:00",
  "end_time": "2026-10-23T16:00:00+08:00"
}


处理顺序：
1. 从 JWT 获取申请人。
2. 通过 D1 判断其是否为有权申请的教师或管理员，以及所属学院是否符合要求。
3. 从 D2 取得教室信息，并检查可申请条件。
4. 在 M2 创建申请记录，并协调 D2 创建 HELD 资源预占。
5. 返回 PENDING_L1 状态。
申请写入和 D2 预占分别位于不同服务，不能用一个本地数据库事务保证原子性。建议采用幂等请求、失败补偿和定期对账，避免出现只有申请、没有预占的悬挂状态。
6.5 审批状态转换
PENDING_L1
一级审批 · 教室管理员
PENDING_L2
二级审批 · 系统管理员
APPROVED
D2 确认占用 CONFIRMED

任一级驳回 → REJECTED；申请人撤销 → CANCELLED；超时 → EXPIRED。三种情况均由 D2 释放对应预占。

当前状态	事件	新状态	D2 动作
PENDING_L1	一级同意	PENDING_L2	维持 HELD
PENDING_L1	一级驳回	REJECTED	RELEASED
PENDING_L2	二级同意	APPROVED	CONFIRMED
PENDING_L2	二级驳回	REJECTED	RELEASED
PENDING_L1 / L2	超时	EXPIRED	RELEASED
PENDING_L1 / L2	申请人撤销	CANCELLED	RELEASED
审批接口不要求前端传入 approval_level，由当前申请状态确定审批级别，并用 D1 验证调用者的身份。
审批拒绝必须提供非空 comment；同一级审批不得重复生效。
