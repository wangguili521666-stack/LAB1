4.6 D2 必须遵守的冲突规则
现有占用	新请求	是否允许
座位 A 已占用	相同时间预约座位 A	不允许
座位 A 已占用	相同时间预约座位 B	允许
教室已整体占用	同时段预约其内部座位	不允许
某座位已占用	同时段申请整间教室	不允许
占用时段 09:00–11:00	预约 11:00–12:00	允许
教室维护中或已停用	任意新预约	不允许
冲突判断必须在数据库事务内完成，不能仅靠先查询、再插入两个独立步骤。
另外，HELD 且未过期的记录与 CONFIRMED 记录都阻止冲突预占；RELEASED 不再阻止预占。

4.7 第一阶段实现约定：教室与座位主数据（2026-10-28 确认）

本阶段实现 4.3 中的教室、座位管理接口；可用性、预占、确认、释放和维修同步属于后续阶段，不以主数据接口代替这些业务。
本阶段以本文和 common.md 为接口依据；仓库尚未提供 contracts/openapi.yaml。

认证与权限：
- 所有主数据接口要求 Bearer Token。D2 将原用户 Token 转发至 D1 GET /api/d1/users/me，从响应提取用户 ID、状态、角色、学院；不读取 D1 数据库，不接受客户端指定操作者或角色。
- 只有 ACTIVE 用户可访问。SYSTEM_ADMIN 可维护全部资源；CLASSROOM_ADMIN 仅能新增或维护自己所属非空学院的资源，不能将资源转出该学院，也不能管理无学院资源。其他角色只读。
- 座位的管理权限继承其教室。修改时在 D2 事务内锁定教室并检查学院，避免并发修改学院导致越权。
- classrooms.college_id 是 D1 学院的逻辑引用，不建立跨库物理外键。创建或修改为非空学院时，通过已定义的 GET /api/d1/colleges 校验；学院不存在返回 422 VALIDATION_ERROR。D1 未实现该接口、超时、返回异常结构或不可用时，返回 503 DEPENDENCY_UNAVAILABLE，不绕过校验。
- 无凭证/凭证无效返回 401；禁用账号、角色或学院权限不足返回 403。D1 依赖故障返回 503。

输入与返回：
- 创建教室时 status 固定初始化为 AVAILABLE；equipment 缺省为 {}，college_id 缺省为 null。创建座位时 status 初始化为 AVAILABLE。
- PATCH /classrooms/{id} 仅允许 building、room_number、college_id、capacity、equipment、status、is_bookable_whole、open_time、close_time；PATCH /seats/{id} 仅允许 seat_number、socket_type、status。PATCH 至少包含一个可修改字段。
- building、room_number、seat_number 为去除首尾空白后的非空字符串，上限分别为 100、30、20 个 Unicode 码点。capacity 为 1..2147483647 的整数；equipment 必须为 JSON 对象；is_bookable_whole 必须为 JSON 布尔值。
- open_time、close_time 为 00:00:00..23:59:59 的 HH:mm:ss。本阶段只维护这两个独立时间字段，不自行规定跨午夜预约规则。
- ID 必须为正的十进制字符串，范围为有符号 BIGINT；请求体不接受数值 ID。未知字段、非法枚举、错误类型、空 PATCH、非对象/非法 JSON 返回 400 VALIDATION_ERROR。
- 列表按 id 升序；building、room_number 使用精确匹配。查询布尔值只接受 true/false；page、page_size、min_capacity 使用十进制整数，page_size 不超过 100。page 默认 1，page_size 默认 20；min_capacity 允许 0。
- 主数据查询返回 4.2 定义的 Classroom / Seat，不额外返回数据库 created_at。不存在的教室或座位返回 404；不存在教室的座位列表也返回 404。
- POST 创建返回 201，GET/PATCH 返回 200。现有契约未规定编号唯一性和创建幂等键，因此不擅自添加编号唯一约束；重复 POST 创建独立记录，相同 PATCH 可重复调用。客户端不得盲目重试结果未知的 POST。
- 将主数据标记为 MAINTENANCE / DISABLED 不覆盖座位自身状态、不删除任何记录。后续资源服务必须同时检查教室与座位状态；本阶段不声称已经实现预约拦截。

审计与依赖失败：
- 已批准在 D2 新增 operation_log_outbox 技术表，由版本化迁移创建。成功写操作及其 D3 审计载荷在同一 D2 MySQL 事务提交；鉴权、参数及业务失败尝试也写入失败审计。
- 日志载荷严格使用 D3 OperationLogCreate，仅含可信操作者、模块、操作、目标、方法、路径、结果、来源 IP；不保存 Token、请求正文或个人资料。路径不含查询字符串。
- 后台使用独立配置的可信服务 Bearer 凭证调用 POST /api/d3/internal/logs。D3 未就绪时保留 PENDING 并重试，资源写入仍可成功；进程重启后继续发送。D3 尚无去重契约，投递为至少一次，超时或进程故障后可能重复。
- 如 D2 数据库不可用，无法持久化的失败审计只输出不含秘密的故障标识，同时返回依赖错误，不声称日志已经保存。

运行检查：
- GET /api/d2/health 无需认证；数据库和本阶段迁移就绪返回 200，data={status:"UP"}；未就绪返回 503 DEPENDENCY_UNAVAILABLE。D3 待发送队列不作为 D2 数据库健康失败条件。
- 本阶段验收对应 D2-01、D2-02、D2-13，以及 D2-12 的主数据停用部分；D2-12 的预约拦截及 D2-03..11、14 待资源占用阶段验收。

4.8 第二阶段：可用性、原子占用与维修联动（2026-10-28 用户确认）

本节覆盖第一阶段关于“尚未实现”的说明；4.3 中全部 D2 接口均纳入实现。不修改 M1/M2/M3/D1/D3 业务代码、前端或 Compose。

可信服务身份与记录访问：
- 为 M1、M2、M3 分别配置独立随机 Bearer 密钥，通过 D2_M1_SERVICE_TOKEN、D2_M2_SERVICE_TOKEN、D2_M3_SERVICE_TOKEN 注入 D2；至少 32 字符、不得重复，不提供默认值，不写入日志。服务密钥独立于 D1 用户 JWT；未配置密钥的服务无法访问。
- M1/M2 可读取主数据及可用性。M1 仅能以 source_module=M1 创建 SEAT 预占，M2 仅能以 source_module=M2 创建 CLASSROOM 预占；确认、释放、查询只能访问自身 source_module。M3 仅允许维修同步。
- 已登录 ACTIVE 用户可读取主数据及可用性。占用记录仅 SYSTEM_ADMIN 可全量只读，CLASSROOM_ADMIN 可只读本学院；普通用户不得读取或写入占用记录。审批、用户预约权限由 M1/M2 通过 D1 校验，D2 不读取其业务表。
- 服务密钥只代表已验证的调用模块，不采信客户端提交的操作者 ID、角色头或任意 source_module。

时间与可用性：
- 输入时间为带时区的 RFC 3339 字符串，必须包含秒，可选 1..3 位毫秒；拒绝无时区、非法日期及超出 MySQL DATETIME 范围的时间。存储为 UTC DATETIME(3)，返回 UTC ISO 8601；区间必须 start_time < end_time，使用 [start_time, end_time)。
- D2 不重复实现 M1 的整点、四小时上限或 M2 的审批规则，也不自行限制查询历史时间。
- BUSINESS_UTC_OFFSET 默认 +08:00，可配置固定偏移。按该偏移解释每日 open_time/close_time；相等表示全天开放，open_time > close_time 表示跨午夜。非全天开放时，一个申请区间必须完整位于某个连续开放窗口内，结束时刻等于关闭时刻允许。
- AvailabilityResult 与 AvailabilityItem 相同：{resource_type, resource_id, classroom_id, available, reason}。search 返回静态筛选匹配的全部资源及判定，不擅自过滤 unavailable；check 对不存在资源返回 404。
- reason 优先级及枚举依次为 CLASSROOM_DISABLED、CLASSROOM_MAINTENANCE、SEAT_DISABLED、SEAT_MAINTENANCE、WHOLE_BOOKING_NOT_ALLOWED、OUTSIDE_OPENING_HOURS、RESOURCE_CONFLICT；可用时为 null。维修来源阻塞与手动教室 MAINTENANCE 均返回 CLASSROOM_MAINTENANCE。
- 搜索筛选严格使用 4.4 白名单；CLASSROOM 的 is_bookable_whole 为 JSON 布尔值。check 不接受 filters；搜索结果按资源 ID 升序。瞬时查询不承诺后续预占成功。
- 只有未过期 HELD 或 CONFIRMED 的重叠记录阻塞；相邻区间不冲突；整教室与内部任意座位互斥，不同座位可同时占用。
- 新建/确认预占与维护操作在同一 D2 事务中先锁定教室，再读取当前资源及冲突记录；不能用普通快照中的“先查再插入”替代并发控制。

预占幂等、状态与超时：
- 创建使用唯一键 (source_module, source_id)。第一次返回 201 HELD；同资源、相同时段的重试返回 200 当前记录，不创建第二份占用；如显式提供截止时间，必须与初次请求一致，否则返回 409 DUPLICATE_OPERATION。未提供时沿用首次截止，不刷新租约。已释放的来源键不复活，需由源模块产生新的业务 ID。
- hold_expires_at 缺省为数据库当前时间加 HOLD_TTL_SECONDS（默认 300 秒）；显式给出时必须晚于数据库当前时间，不接受 null。D2 不擅自把它绑定为业务时段开始时间，M2 应按审批截止时间传入。
- confirm：未过期 HELD 经资源状态、维修阻塞、开放时间及冲突复核后转 CONFIRMED；重复确认 CONFIRMED 返回 200；RELEASED 或已过期 HELD 返回 409 INVALID_STATE。过期确认会先将 RELEASED 与审计持久化，再返回错误。
- release：HELD / CONFIRMED 转 RELEASED，重复释放返回 200，不重新占用资源。reason 可选、非空字符串最长 255 字符；业务释放原因由源模块保存，不新增未经批准的业务字段，也不将请求正文写入审计。
- CONFIRMED / RELEASED 响应 hold_expires_at 为 null；数据库保留初始截止用于追踪和幂等比对。状态查询和列表筛选将已到期 HELD 视为 RELEASED，后台定时物理释放；即使 worker 暂停，过期记录也不阻塞新请求。
- EXPIRY_POLL_MS 默认 5000，后台分批释放过期 HELD 并在同一事务写审计。确认/释放/定时任务竞争只允许一次合法转换，不能重新确认已释放记录。
- GET /reservations 额外支持通用 page、page_size；其他筛选保持 4.3，按 id 升序。服务查询自动限制为本模块；学院管理员自动限制本学院。
- 不可预约时创建/确认返回 409 RESOURCE_CONFLICT，消息包含已定义的 reason；缺字段/格式错误为 400，截止已过期为 422，未知资源为 404，来源不符/越权为 403。

维修来源及乱序：
- 新增 D2 maintenance_blocks：ticket_id BIGINT 主键、classroom_id D2 内部外键、active BOOLEAN、revision INT、updated_at DATETIME(3)。每个工单永久绑定首次同步的教室，不删除停用记录。
- M3 必须传正整数 revision（1..2147483647），在每个工单需要同步的状态变化时递增。同版本同内容幂等，旧版本忽略；同版本不同 active 或更换教室返回 409 INVALID_STATE。新版本更新状态，即使 active 相同也保存新 revision。
- 多工单 active=true 取并集。释放某工单不会清除其他工单、手动 MAINTENANCE 或 DISABLED；不修改 classrooms.status，不改写或删除既有预占和预约。
- 响应 maintenance_blocked 表示存在 active 来源或手动 MAINTENANCE；它不表示 DISABLED 的资源可以开放。返工通过更高版本 active=true 重新生效。
- 原 M3 文档示例缺少 revision，需 M3 负责人按本节同步；缺失 revision 的旧请求返回 400，不静默降级为不安全的最后写入覆盖。

审计与验收补充：
- 所有占用状态写入、维修变更与审计 outbox 同事务；幂等调用也记录成功尝试。来源模块可从目标占用或工单记录追溯。
- 后台过期操作使用 action=RESERVATION_EXPIRE、user_id=null、request_method=SYSTEM、ip_address=null，路径为 D2 reservations；均为 D3 现有载荷字段，不增加载荷字段。D3 的最终接入和至少一次投递去重仍需联调。
- 第二阶段覆盖 D2-03..14，并新增 D2-15..20 验收多工单阻塞、维修乱序/返工、状态竞态、来源幂等、开放窗口和服务权限边界。
