1 和 M2 不应该自己重新实现冲突检测，而是统一通过 D2 查询、预占、确认、释放资源。M3 的维修状态也应通过 D2 影响可预约性。
4.1 Database Schema
数据表	字段及类型
classrooms	id BIGINT PK, building VARCHAR(100), room_number VARCHAR(30), college_id BIGINT NULL, capacity INT, equipment JSON, status VARCHAR(20), is_bookable_whole BOOLEAN, open_time TIME, close_time TIME, created_at DATETIME
seats	id BIGINT PK, classroom_id BIGINT FK, seat_number VARCHAR(20), socket_type VARCHAR(20), status VARCHAR(20), created_at DATETIME
resource_reservations	id BIGINT PK, resource_type VARCHAR(20), resource_id BIGINT, classroom_id BIGINT FK, source_module VARCHAR(10), source_id BIGINT, start_time DATETIME, end_time DATETIME, status VARCHAR(20), hold_expires_at DATETIME, created_at DATETIME
重要枚举：
- classrooms.status、seats.status：AVAILABLE / MAINTENANCE / DISABLED
- seats.socket_type：NONE / FIXED / RAIL
- resource_reservations.status：HELD / CONFIRMED / RELEASED
- resource_reservations.resource_type：SEAT / CLASSROOM

4.4 可用资源查询的明确规范
这部分必须统一，否则 M1 和 M2 很难并行开发。
POST /api/d2/availability/search
请求：
{
  "resource_type": "SEAT",
  "start_time": "2026-10-23T09:00:00+08:00",
  "end_time": "2026-10-23T11:00:00+08:00",
  "filters": {
    "college_id": "1",
    "building": "教学楼A",
    "classroom_id": "201",
    "socket_type": "FIXED"
  }
}


返回：
{
  "code": "OK",
  "message": "success",
  "data": [
    {
      "resource_type": "SEAT",
      "resource_id": "301",
      "classroom_id": "201",
      "available": true,
      "reason": null
    }
  ],
  "request_id": "req-004"
}


filters 的字段应按资源类型校验：
resource_type	合法筛选字段
SEAT	college_id?, building?, classroom_id?, socket_type?
CLASSROOM	college_id?, building?, room_number?, min_capacity?, is_bookable_whole?
结果只包含满足静态筛选条件的资源；每个资源再附加给定时间段的可用性判定。
M1 与 M2 可选择只显示 available=true 的资源，但不能把静态 status=AVAILABLE 直接当作时间段可预约。
4.5 资源预占
POST /api/d2/reservations
{
  "resource_type": "CLASSROOM",
  "resource_id": "201",
  "source_module": "M2",
  "source_id": "601",
  "start_time": "2026-10-23T14:00:00+08:00",
  "end_time": "2026-10-23T16:00:00+08:00",
  "hold_expires_at": "2026-10-23T12:00:00+08:00"
}


成功时返回 Reservation，状态为 HELD。
失败时：
{
  "code": "RESOURCE_CONFLICT",
  "message": "该教室已有重叠的资源占用",
  "data": null,
  "request_id": "req-005"
}


4.6 D2 必须遵守的冲突规则
现有占用	新请求	是否允许
座位 A 已占用	相同时间预约座位 A	不允许
座位 A 已占用	相同时间预约座位 B	允许
教室已整体占用	同时段预约其内部座位	不允许
某座位已占用	同时段申请整间教室	不允许
占用时段 09:00–11:00	预约 11:00–12:00	允许
教室维护中或已停用	任意新预约	不允许
冲突判断必须在数据库事务内完成，不能仅靠先查询、再插入两个独立步骤。
另外，HELD 且未过期的记录与 CONFIRMED 记录都阻止冲突预占；RELEASED 不再阻止预占。
