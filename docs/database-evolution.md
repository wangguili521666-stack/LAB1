# 数据库演进与集成测试约定

## 使用

首次运行 `bash start.sh`：创建六个模块数据库，按版本迁移，再执行各模块 seeds，最后等待健康检查。已有环境同样执行此命令升级；不要删除 mysql_data 卷。

已有容器中重新执行迁移和种子：`npm run db:replay`。它使用容器已有连接配置，不需要复制密码。此命令不构建新镜像；修改代码后先用 start.sh 构建部署。

单模块：`docker compose exec -T d1 npm run migrate`；仅同步种子：`docker compose exec -T d1 npm run seed`。

新增结构：在 backend/模块/migrations 新增三位递增版本，如 D1 的 `004_add_example.sql`（名称仅为格式示例）。执行 `npm --prefix backend/D1 run migration:register`，同时提交新 SQL 和 migrations.sha256.json。已经登记的脚本禁止修改或删除，登记命令也拒绝覆盖旧校验值。清单统一 LF/CRLF 换行，避免跨平台误报。其他模块同理。

迁移记录由各模块自己的 schema_migrations 管理，D3 使用 d3_schema_migrations。重复运行跳过成功版本。MySQL DDL 不能整体事务回滚：失败须停止发布、检查实际执行状态，由负责人提供前向修复；不要通过删迁移记录或删库重试。

## 种子与业务数据

各模块 seeds/*.sql 与 migrations 分开；npm run migrate 成功后自动运行 seed，失败则阻止容器启动。种子使用事务及数据库命名锁，并采用唯一键与 INSERT IGNORE 保持幂等，保留管理员已修改的配置。

D1 维护默认角色及权限字典，M1 维护预约默认参数，M3 维护报修类型；其余模块暂无必要种子。用户、预约、申请、维修工单、公告等业务实例不得加入种子。

历史 SQL 中的初始化语句保持原样，避免重写已执行历史；从本次起，新增初始化数据写入 seeds，并和对应结构变更同一次提交。角色权限关联仍由历史首次初始化和管理功能维护，不在每次 seed 时重新授予管理员撤销的权限。修改既有默认值不会覆盖数据库中的自定义值，如需转换已有数据，应新增经评审的数据迁移。

## 部署窗口的等效机制：每次 CI 完全隔离

正式集成验收统一执行 `npm run test:all`（或 `npm run ci`）。scripts/ci.sh 每次复制独立工作目录、生成独立凭证、创建唯一 Compose 项目与数据库卷，使用动态端口，等待所有服务健康后再测试。因此其他模块部署共享环境不会导致此轮验收误报。测试结束只清理本次 CI 自有资源。

完整 CI 从空数据库启动全系统，再对六模块重复执行迁移与种子两轮，之后运行集成用例。`npm test` 仅单元测试和构建，不能替代完整验收。

共享演示环境只用于手动联调，不用于正式 CI 判定。若确需在共享环境执行 scripts/integration.mjs，必须由组内负责人先约定独占窗口：暂停全部模块部署，确认六模块健康，再测试，结束后解除窗口。直接运行该脚本不会自动获得跨机器锁；不得把部署期间的结果作为验收结论。跨机器的正式流水线仍必须使用上述独立环境。

## 验收与限制

需要 Node.js >=22、Docker Engine 与 Compose。完整运行：`npm run test:all`。检查日志中的空库启动、两轮迁移重放和集成断言；失败不得部署。

校验清单属于代码审查约束，不能替代数据库权限控制：禁止手工改共享库；生产建议使用独立迁移账号和仅 DML 的应用账号。新增迁移、种子及清单需相关模块负责人审查。
