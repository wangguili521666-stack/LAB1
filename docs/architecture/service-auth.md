# 服务间认证与模块集成（2026-10-29）

用户授权本次跨模块统一及 M1/M3 后端补齐。保留 D2/D3 各自既有认证入口，统一调用方配置和文档；不复用用户 JWT 或一枚全系统服务密钥。

| 调用链 | 请求头 | 调用方配置 | 接收方配置 |
| --- | --- | --- | --- |
| M2 → D1 权限校验 | X-Service-Token | D1_SERVICE_TOKEN | D1_M2_SERVICE_TOKEN |
| M1/M2/M3 → D2 | Authorization: Bearer <token> | D2_SERVICE_TOKEN | D2_M1/M2/M3_SERVICE_TOKEN |
| M1/M2/M3/D2 → D3 | X-D3-Service-Token | D3_SERVICE_TOKEN | D3_SERVICE_TOKENS JSON，模块名为键 |
| 浏览器 → 业务模块 | Authorization: Bearer <用户 JWT> | 登录后保存用户令牌 | M1/M3/D3 向 D1 查询实时身份 |

Compose 将根目录每条调用链的独立密钥映射到调用方和接收方。start.sh 只补充缺失的服务密钥，不更换已有数据库密码。所有服务密钥必须保密，不进入浏览器、示例输出或 Git。

## 数据与一致性

六个模块分别拥有数据库账号，只访问本模块数据。资源冲突、整教室占用、维修阻塞以 D2 为唯一权威；跨模块只使用 HTTP。

M1 先持久化 CREATING 记录，再用预约 ID 幂等预占、确认 D2；取消与违约先持久化 CANCELLING/EXPIRING，再释放资源。定时工作器重试中间状态，网络错误不假装完成。业务审计和提醒事件持久化在本库，D3 用来源事件 ID 去重。

M3 按工单维护单调 revision、maintenance_active 和 sync_pending。开始维修及验收通过后同步 D2；同步未完成时禁止下一次状态操作，工作器持续重试。多个工单分别保留阻塞来源；验收一个工单不会恢复其他工单仍阻塞的教室。返工保持阻塞，完工待验收仍阻塞。超时仅首次升级一次（优先级最多 3），保留 ESCALATE 记录。

M2 保留现有申请与审批实现，仅适配认证。其 D3 审计仍为尽力发送，尚未增加持久化 Outbox；不能据此宣称审计绝不丢失。

## 运行与验收

统一部署入口 ./start.sh，所有服务执行自己的迁移后启动。移除全局固定 MySQL 容器名，允许独立 Compose 项目并存。数据库端口和前端端口通过环境变量配置。已有数据库不清空、不重置密码。

首次管理员创建：先通过正常页面注册，再由拥有部署权限的操作员执行：

```sh
docker compose exec d1 node scripts/grant-role.js <用户名> SYSTEM_ADMIN
```

同一命令可授予 PROPERTY_ADMIN、REPAIR_WORKER、TEACHER、CLASSROOM_ADMIN 等已定义角色，不提供默认管理员密码或公开提权接口。

测试脚本 scripts/integration.mjs 仅在独立测试环境运行，会创建带时间戳的测试用户、教室、预约和工单。覆盖真实六服务 HTTP 链路、并发冲突、两级审批、维修返工、多工单阻塞、重复评价及审计。

## 动态 RBAC 与签到屏幕扩展

D1→D3 新增专属 D3_D1_SERVICE_TOKEN。M1/M3/D2/D3 消费 D1 返回的实时 permissions；M2 internal/authorize 改查数据库关联，取消固定业务角色映射。资源管理和签到展示的非系统管理员仍受学院约束；权限本身不绕过学院或业务所有权。

D1 的聚合接口只通过用户令牌请求三个公开 /me 接口；失败返回明确 503。管理操作在串行锁保护下变更并写审计 Outbox，不允许撤销最后管理员。

教室屏幕使用已认证会话，不提供公开查询签到码接口；当日编码有效期由服务端给出，前端使用服务器时间偏移校准并在到期/错误时隐藏。教室设备需保持管理员会话有效；登录到期后重新登录。
